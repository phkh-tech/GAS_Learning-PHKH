Selection behaviorHow a parent picks a child. Try Select Children In Order tries the children top to bottom and takes the first one whose enter conditions pass. Try Select Children At Random shuffles them first. All children have weight 1.0, so the odds are equal.Cách state cha chọn state con. Try Select Children In Order thử các con từ trên xuống dưới và lấy con đầu tiên thỏa enter condition. Try Select Children At Random xáo trộn các con trước.   • The triggers used here are On State Completed, On State Succeeded, On State Failed and On Tick (checked every update).
  • The targets used are Goto State (a named state), Next State (the next sibling) and Succeeded (finish the whole tree).
  • Các trigger dùng ở đây là On State Completed, On State Succeeded, On State Failed và On Tick (kiểm tra mỗi lần update).
  • Các target dùng là Goto State (một state có tên), Next State (state anh em kế tiếp) và Succeeded (kết thúc toàn bộ cây).

Một số state ở đây (Wait After Flank, Wait After Evasion, Wait after Landing, Default) dựa vào cơ chế "chạy lại từ Root" này.

BP_CombatAIController has no graph logic at all. Its EventGraph only holds a comment saying the StateTree starts automatically once the pawn is possessed. All of the behavior lives in the StateTree and its tasks. Swapping the tree for another enemy means changing the StateTree asset on the controller's StateTreeAI component, or making a second controller.

  2. If that pawn is valid, sets Target Player Location = its actor location.
  3. Sets Distance to Target = distance from Attack Source (bound to the enemy) to the player location.

5. State-by-state walkthrough5. Đi qua từng state

Root (Try Select Children In Order)

Each time the tree (re)selects from Root, it tries the five children top to bottom: Dead → Select Behaviors at Random → Evading → Launched → Default, and enters the first one whose enter conditions pass.

Mỗi lần cây chọn (lại) từ Root, nó thử năm state con từ trên xuống: Dead → Select Behaviors at Random → Evading → Launched → Default, và vào state đầu tiên thỏa enter condition.

Root has one On Tick transition: if Actor.Current HP ≤ 0, go to Dead. This uses a Compare Float condition (operator Less Or Equal, Right = 0). Because it sits on Root, which is always active, it is checked every update no matter what the enemy is doing, so death interrupts everything.

Root có một transition On Tick: nếu Actor.Current HP ≤ 0 thì đi tới Dead. Nó dùng condition Compare Float (operator Less Or Equal, Right = 0). Vì nằm trên Root, vốn luôn active, nên nó được kiểm tra mỗi lần update bất kể kẻ địch đang làm gì. Nhờ vậy cái chết sẽ ngắt mọi hành động khác.

Dead

  • Description: "When the enemy's HP falls to zero, finish the StateTree".
  • Enter condition: Compare Float, Actor.Life Bar Widget.CurrentHealth ≤ 0. Note that this reads the life bar widget's health, while Root's transition reads the pawn's Current HP variable. Both must agree (see section 10).
  • Task: Debug Text "Dead".
  • Transitions: On Tick → Succeeded, and On Completed → Succeeded. "Succeeded" as a target means stop the whole tree with success. So on its first update after entering, the tree ends and the enemy has no more AI logic. The body's own death handling (ragdoll, On Enemy Died → spawner) is done in BP_EnemyNPC, not here.
  • State tag: Status.Death. This is a StateTree state tag, used to query which state is active. It is not added to the actor's ability system component.
  • Mô tả: "When the enemy's HP falls to zero, finish the StateTree" (khi HP kẻ địch về 0, kết thúc StateTree).

  • Task: Debug Text "Dead".
  • Transition: On Tick → Succeeded, và On Completed → Succeeded. Target "Succeeded" nghĩa là dừng toàn bộ cây với kết quả thành công. Vì vậy ngay lần update đầu tiên sau khi vào state, cây kết thúc và kẻ địch không còn logic AI nào nữa. Phần xử lý chết của cơ thể (ragdoll, On Enemy Died → spawner) được làm trong BP_EnemyNPC, không phải ở đây.
  • State tag: Status.Death. Đây là state tag của StateTree, dùng để truy vấn state nào đang active. Nó không được thêm vào ability system component của actor.

Select Behaviors at Random (Try Select Children At Random)

  • Description: "Randomly choose between Idling, Flanking and Attacking".
  • Enter condition: Object Is Valid on Target Player Character. The enemy only picks a behavior if a player pawn exists.
  • Children: Attacking, Idling, Flanking, all with weight 1. Each time this state is entered, the three are shuffled and the first valid one is chosen. Each behavior has roughly a 1/3 chance; Attacking always passes because one of its two children is always valid.
  • On Tick transition → Launched when Is Character Grounded with Must Be on Air = true passes, which really means "the enemy is airborne". Because this sits on the parent, any behavior is interrupted the moment the enemy gets knocked into the air (for example by your claw attack or a launch).
  • Mô tả: "Randomly choose between Idling, Flanking and Attacking" (chọn ngẫu nhiên giữa Idling, Flanking và Attacking).
  • Enter condition: Object Is Valid trên Target Player Character. Kẻ địch chỉ chọn hành vi khi có pawn người chơi.
  • State con: Attacking, Idling, Flanking, đều có weight 1. Mỗi lần vào state này, ba con được xáo trộn và con hợp lệ đầu tiên được chọn. Mỗi hành vi có khoảng 1/3 cơ hội; Attacking luôn hợp lệ vì một trong hai con của nó luôn thỏa điều kiện.
  • Transition On Tick → Launched khi Is Character Grounded với Must Be on Air = true thỏa, tức thực chất là "kẻ địch đang ở trên không". Vì nằm trên state cha, mọi hành vi đều bị ngắt ngay khi kẻ địch bị hất lên không (ví dụ bởi đòn claw của bạn hoặc một cú launch).

Chuỗi Melee:

  • Tasks: Delay 0.5 s ± 0.2 s, Debug Text "Idling", and Face Actor (player). The Delay is the only task that finishes.

Flanking

  2. Move to Flanking Point: Move To FlankingTarget with radius 5 and strafe allowed, at speed 300, while Face Actor keeps the player in focus. The result is that the enemy circles you while watching you. On Succeeded → Next.
  3. Wait After Flank: Delay 0.4 s ± 0.2 s while facing the player. It has no transitions, so when it completes the tree restarts from Root.
  1. Find Flanking Point: EnvQuery_Flank với Min Flank Distance = 350 và Max Flank Distance = 750, mode Random Best 25%. Kết quả ghi vào FlankingTarget. Thành công → Next; thất bại → Idling (Goto trực tiếp, nên bỏ qua bước chọn ngẫu nhiên).

Evading

Reached mainly through the many "Is In Danger" tick transitions. It shows the debug text "Evading", faces the player, and runs three steps:

Chủ yếu được vào qua các transition tick "Is In Danger". Nó hiện debug text "Evading", quay mặt về người chơi, và chạy ba bước:

  1. Find Evasion Point: EnvQuery_Evade with sample distance 100–250 and evasion distance 120–300, mode Random Best 5%. The result is written to FlankingTarget (the same parameter Flanking uses; there is no separate evasion parameter).

Launched

  • Description: "If the character leaves the ground, we abort other behaviors and wait for landing before resuming."

  • Wait for Landing: binds to the character's LandedDelegate and finishes when the character lands.
  • Wait after Landing: Delay 0.3 s ± 0.2 s, a short recovery.
  • Exit: Launched's On Completed → Root resumes normal behavior.
  • Mô tả: "If the character leaves the ground, we abort other behaviors and wait for landing before resuming." (Nếu nhân vật rời mặt đất, hủy các hành vi khác và chờ tiếp đất rồi mới tiếp tục.)

  • Wait for Landing: bind vào LandedDelegate của character và kết thúc khi character tiếp đất.
  • Wait after Landing: Delay 0.3 s ± 0.2 s, một khoảng hồi phục ngắn.

6. A play-through, tick by tick6. Một trận đấu, từng tick một

  1. The spawner spawns BP_EnemyNPC. BP_CombatAIController possesses it and the StateTreeAI component starts the tree. Get Player Info begins ticking.
  2. Root selects in order:
    • Dead? HP > 0, so no.
    • Select Behaviors? Yes once the global task has found the player pawn.
    • The random pick lands on, say, Flanking.
  3. Find Flanking Point succeeds → the enemy strafes around you at speed 300, always facing you → it pauses for about 0.4 s → back to Root.
  4. Next pick: Attacking. You are 600 units away, so Close in for Melee runs at speed 600. When the move succeeds it goes to Melee, whose enter check (≤ 100) passes.
  5. Melee Attack randomly picks Charged Attack → the montage plays → On Attack Completed fires → Find Fallback Point → the enemy backs off 150–300 units while facing you → Wait After Melee → Root.
  6. You swing at it. Your attack calls Notify Danger on the enemy, which stores Last Danger Time/Location. Between 0.35 s and 0.75 s later, Is In Danger becomes true if you are inside its 120° view cone. Each tick in that window, the active Evading transition rolls its random check (0.9 while idle, 0.6 while moving, 0.25 while closing in) → Evading: a quick sidestep at speed 600.
  7. Your claw launches it into the air → the tick transition on Select Behaviors fires → Launched → it waits for Landed → a short pause → Root.
  8. HP reaches 0 → Root's tick transition → Dead (if the life bar's CurrentHealth is also ≤ 0) → next tick the tree finishes with Succeeded.
  1. Spawner spawn ra BP_EnemyNPC. BP_CombatAIController possess nó và component StateTreeAI khởi động cây. Get Player Info bắt đầu tick.
  2. Root chọn theo thứ tự:
    • Dead? HP > 0, nên không.
    • Select Behaviors? Có, khi global task đã tìm thấy pawn người chơi.
    • Chọn ngẫu nhiên rơi vào, giả sử, Flanking.
  3. Find Flanking Point thành công → kẻ địch strafe vòng quanh bạn với tốc độ 300, luôn nhìn về phía bạn → dừng khoảng 0.4 s → quay về Root.
  4. Lần chọn tiếp theo: Attacking. Bạn đang cách 600 unit, nên Close in for Melee chạy với tốc độ 600. Khi di chuyển thành công, nó đi tới Melee, và điều kiện vào (≤ 100) được thỏa.
  5. Melee Attack chọn ngẫu nhiên Charged Attack → montage được phát → On Attack Completed được gọi → Find Fallback Point → kẻ địch lùi 150–300 unit mà vẫn nhìn bạn → Wait After Melee → Root.
  6. Bạn vung đòn vào nó. Đòn đánh của bạn gọi Notify Danger trên kẻ địch, lưu lại Last Danger Time/Location. Từ 0.35 s đến 0.75 s sau đó, Is In Danger trở thành true nếu bạn nằm trong nón tầm nhìn 120° của nó. Mỗi tick trong khoảng thời gian đó, transition Evading đang active sẽ tung xúc xắc (0.9 khi đứng yên, 0.6 khi di chuyển, 0.25 khi đang áp sát) → Evading: một cú né ngang nhanh với tốc độ 600.
  7. Đòn claw của bạn hất nó lên không → transition tick trên Select Behaviors kích hoạt → Launched → nó chờ Landed → dừng ngắn → Root.
  8. HP về 0 → transition tick của Root → Dead (nếu CurrentHealth của thanh máu cũng ≤ 0) → tick tiếp theo cây kết thúc với Succeeded.

10. Things worth knowing / fixing10. Điều cần biết / cần sửa

1. BP_CombatEnemy no longer matches the tree's context1. BP_CombatEnemy không còn khớp với context của cây The tree's Context Actor Class is BP_EnemyNPC, and four nodes cast Character to BP_EnemyNPC. BP_CombatEnemy still points at BP_CombatAIController, but it is a plain Character, not a BP_EnemyNPC. If a BP_CombatEnemy is placed in a level, its StateTree will not get a valid context actor; expect a context error in the log and no AI. Either give it a different controller/tree, or stop using it. The spawner already uses BP_EnemyNPC. Context Actor Class của cây là BP_EnemyNPC, và bốn node cast Character sang BP_EnemyNPC. BP_CombatEnemy vẫn trỏ tới BP_CombatAIController, nhưng nó chỉ là một Character thường, không phải BP_EnemyNPC. Nếu đặt một BP_CombatEnemy vào level, StateTree của nó sẽ không nhận được context actor hợp lệ; bạn sẽ thấy lỗi context trong log và không có AI. Hãy cho nó một controller/cây khác, hoặc thôi không dùng nó nữa. Spawner hiện đã dùng BP_EnemyNPC.
2. Two different HP sources decide death2. Hai nguồn HP khác nhau cùng quyết định cái chết Root's transition checks Actor.Current HP ≤ 0, but Dead's enter condition checks Actor.Life Bar Widget.CurrentHealth ≤ 0. If only one of them reaches 0, the transition fires but Dead's enter condition blocks it, and the enemy keeps fighting. This can happen, for example, if GAS damage updates the widget but not the Blueprint Current HP. While moving to GAS, bind both to the same source, ideally the GAS Health attribute or a State.Death tag check. Note also that this state's tag is Status.Death, while your GAS death tag is State.Death. Transition của Root kiểm tra Actor.Current HP ≤ 0, nhưng enter condition của Dead lại kiểm tra Actor.Life Bar Widget.CurrentHealth ≤ 0. Nếu chỉ một trong hai về 0, transition được kích hoạt nhưng enter condition của Dead chặn lại, và kẻ địch tiếp tục chiến đấu. Điều này có thể xảy ra, ví dụ khi damage từ GAS cập nhật widget nhưng không cập nhật biến Blueprint Current HP. Khi chuyển sang GAS, hãy bind cả hai vào cùng một nguồn, lý tưởng nhất là attribute Health của GAS hoặc kiểm tra tag State.Death. Lưu ý thêm: tag của state này là Status.Death, trong khi tag chết trong GAS của bạn là State.Death.
3. "Default" is unreachable; "Evading" catches the fallback3. "Default" không bao giờ được chọn; "Evading" hứng trường hợp dự phòng Root selects children in order: Dead, Select Behaviors, Evading, Launched, Default. Evading has no enter condition, so whenever Select Behaviors can't be entered (for example on the very first selection, before Get Player Info has ticked, or when there is no player pawn), Root picks Evading instead of Default. In that case the enemy tries to evade with no threat. Launched is still reached through its tick transition.
Fix: drag Evading below Default in the tree. Goto transitions don't care about order, so the "→ Evading" rules keep working, and Default becomes the real fallback again. Alternatively, give Evading an enter condition. Root chọn các con theo thứ tự: Dead, Select Behaviors, Evading, Launched, Default. Evading không có enter condition, nên mỗi khi không vào được Select Behaviors (ví dụ ở lần chọn đầu tiên, trước khi Get Player Info kịp tick, hoặc khi không có pawn người chơi), Root sẽ chọn Evading thay vì Default. Khi đó kẻ địch cố né dù chẳng có mối đe dọa nào. Launched vẫn được vào qua transition tick của nó.
Cách sửa: kéo Evading xuống dưới Default trong cây. Transition Goto không phụ thuộc thứ tự, nên các luật "→ Evading" vẫn hoạt động, và Default trở lại làm phương án dự phòng thật sự. Hoặc bạn có thể thêm enter condition cho Evading.
4. Evasion reuses FlankingTarget4. Việc né dùng lại FlankingTarget Find Evasion Point writes into the same FlankingTarget parameter as Flanking. It is harmless today, because the two never run at the same time, but an EvadeTarget parameter would make the tree easier to read. Find Evasion Point ghi vào cùng parameter FlankingTarget với Flanking. Hiện tại thì vô hại, vì hai thứ này không bao giờ chạy cùng lúc, nhưng một parameter EvadeTarget riêng sẽ giúp cây dễ đọc hơn.
5. Leftover nodes in the task Blueprints5. Node thừa còn sót trong các Blueprint task Combo Attack, Charged Attack and Wait For Landing still contain disconnected Bind/Unbind/Call nodes targeting BP_CombatEnemy_C, left over from the migration. They never execute, but deleting them avoids confusion and removes the hard reference to BP_CombatEnemy. Combo Attack, Charged Attack và Wait For Landing vẫn còn các node Bind/Unbind/Call không được nối nhắm tới BP_CombatEnemy_C, sót lại từ lúc chuyển đổi. Chúng không bao giờ chạy, nhưng xóa đi sẽ tránh gây nhầm lẫn và bỏ được hard reference tới BP_CombatEnemy.
6. Attacks always "succeed"6. Đòn tấn công luôn "thành công" The attack tasks finish with success both when the montage completes and when it is interrupted (for example when the enemy gets hit, because Apply Damage stops the montages). The tree therefore always goes to Find Fallback Point after an attack attempt, even an interrupted one. That is fine for this design; just be aware of it. Các task tấn công kết thúc thành công cả khi montage chạy xong lẫn khi bị ngắt (ví dụ khi kẻ địch bị đánh trúng, vì Apply Damage dừng các montage). Vì vậy sau mỗi lần thử tấn công, kể cả bị ngắt, cây luôn đi tới Find Fallback Point. Với thiết kế này thì không sao; chỉ cần bạn biết điều đó.
GAS migration idea (ties into your learning plan)Ý tưởng chuyển sang GAS (gắn với lộ trình học của bạn) Replace Do AI Combo Attack with a small task that calls Try Activate Ability by Tag on the enemy's ASC, and finishes when the ability ends. Replace the two HP checks with a condition that reads the Health attribute or checks the State.Death tag. The StateTree structure stays exactly the same; only the "hands" change. Thay Do AI Combo Attack bằng một task nhỏ gọi Try Activate Ability by Tag trên ASC của kẻ địch, và kết thúc khi ability kết thúc. Thay hai phép kiểm tra HP bằng một condition đọc attribute Health hoặc kiểm tra tag State.Death. Cấu trúc StateTree giữ nguyên hoàn toàn; chỉ có "đôi tay" thay đổi.

11. How to watch it run11. Cách quan sát cây chạy

  • Debug text: in PIE, each behavior state prints its name ("Idling", "Flanking", "Attacking", "Evading", "Launched", "Dead") above the enemy's head.
  • StateTree Debugger: open ST_CombatEnemy, open Window → Debugger, press record, then play. You can scrub the timeline and see which states were active and which transitions fired each frame.
  • Gameplay Debugger: in PIE press ' (apostrophe) while looking at the enemy. The StateTree category shows the active state path; the AI/Navigation categories show the Move To path.
  • EQS: to see why a Find…Point state failed, open the EnvQuery assets and use an EQS Testing Pawn with the same parameter values listed above.
  • Debug text: trong PIE, mỗi state hành vi in tên của nó ("Idling", "Flanking", "Attacking", "Evading", "Launched", "Dead") phía trên đầu kẻ địch.
  • StateTree Debugger: mở ST_CombatEnemy, mở Window → Debugger, bấm record, rồi play. Bạn có thể kéo timeline để xem state nào active và transition nào được kích hoạt ở từng frame.
  • Gameplay Debugger: trong PIE bấm ' (dấu nháy đơn) khi đang nhìn vào kẻ địch. Category StateTree hiện đường dẫn state đang active; category AI/Navigation hiện đường đi của Move To.
  • EQS: để xem vì sao một state Find…Point thất bại, mở các asset EnvQuery và dùng EQS Testing Pawn với cùng giá trị parameter đã liệt kê ở trên.
